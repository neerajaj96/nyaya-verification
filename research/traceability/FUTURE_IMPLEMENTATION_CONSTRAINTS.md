# Future Implementation Constraints (Binding on Any Verifier Work)

These constraints derive from Phase 0–2A evidence. Violating one requires a
dated, sourced amendment — never silence. D1/D5/D6/D7 remain OPEN; the
constraints below bind the SHAPE of future work, not its outcomes.

1. STRATUM AWARENESS: the verifier MUST know which doctrinal stratum it is
   implementing (NS / Bhāṣya / Vārttika / TS / specified-later), per verdict,
   per run. Untagged verdicts are non-conforming outputs.
2. NO SINGLE "INDIAN LOGIC" SEMANTICS: the verifier MUST NOT expose one
   undifferentiated semantics. Minimum: NS-mode vs TS-mode parameters on
   proof-objects, fallacy labels, and promotion checks (STRATUM_SCOPED_
   SEMANTICS.md).
3. NO TS→GAUTAMA PROJECTION: TS machinery (pakṣatā, guarded vyāpti,
   bivalent concomitance, upādhi-proof, blocking-theory routing) MUST NOT be
   presented as Gautama-era doctrine. NS-mode checks use R1–R3/C1–C5 only.
4. UNKNOWN STAYS UNKNOWN: missing evidence (all G- gaps; siṣādhayiṣā;
   trairūpya; kevala mechanics) MUST be represented as unknown/DEFERRED
   states, never defaulted (no closed-world completion over gaps).
5. DEFEATER ≠ ABSENCE: counterexample evidence (S5c exhibited, scope-
   matched) MUST be typed apart from mere absence of proof (S5a/S5b, N1–N4
   in D6_COUNTEREXAMPLE_PREGATE.md). Untyped defeater inputs are rejected
   at the interface.
6. NON-COLLAPSED HETVĀBHĀSA: HETVABHASA_NONCOLLAPSE_CONSTRAINTS.md C-NC1–C7
   are mandatory: taxonomy-parameterized verdicts, separate A/C modes,
   provenance-carrying superclasses only, segregated gold labels.
7. SCOPED UPĀDHI: only `suspected_condition` annotations until U1–U3
   execution exists (D5_UPADHI_PREGATE §2–§3); NO blocking on suspicion; NO
   "H ∧ U → S" encoding as classical meaning.
8. NO FREQUENCY PROMOTION: support/confidence (or any count) MUST NOT be
   promoted to vyāpti silently (D7 §"Why frequency high ⇏ vyāpti";
   NS 2.1.37 + TS vajra). Frequency inputs, if ever used, enter ONLY via
   stratum promotion checks (C1–C5 NS / §7-D TS) with non-equivalence labels.
9. PROVENANCE ON ABSTRACTIONS: every engineering abstraction (thresholds,
   flags, scores, superclasses, assumed facts) MUST carry {stratum
   approximated, differences introduced, decision dependency (D#)}.
   Unprovenanced abstractions are removed, not grandfathered — INCLUDING
   baseline fields if reused (`upadhi` flag, strength table, assumed-hetu).
10. SEPARATE TRACEABILITY: classical claims and computational semantics MUST
    be separately traceable end-to-end (PRIMARY TEXT → INTERPRETATION →
    CODE → FORMALIZATION with per-arrow verdicts). A verdict citing only
    code, or only text, is incomplete.
11. ENQUIRY-GATING BEFORE ASSENT (VARTTIKA_SUPPORTED): attempt-gating
    (R1–R3-style) and assent-evaluation are SEPARATE stages; a valid
    conclusion outside the enquiry track is NOT a counterexample to gating,
    and gated-out pairs are NOT verdicts against them.
12. ADMISSION BEFORE WEIGHING (Vārttika 1-2-8/9 + 2.1.38): chargers and
    counterexhibits MUST pass admission (proved? scope-matched? admitted
    locus?) BEFORE any force comparison. Weighing unadmitted inputs is a
    documented error.
